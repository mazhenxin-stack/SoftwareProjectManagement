## 1. 本组项目组织情况

### 1.1 项目背景与边界
本组以学校"校园活动报名与签到管理系统"为统一项目情境，按《软件项目管理》综合实验要求，重点完成项目管理过程文档和版本协作过程，不涉及完整业务系统的开发。项目纳入范围限定为活动信息发布、学生报名、名单审核、签到与签到统计、统计结果导出五类功能的设计文档；明确不纳入支付、统一身份认证对接、高并发优化、移动端 App 与正式部署。

### 1.2 团队角色与分工
本组采用"项目经理 + 计划负责人 + 配置管理员 + 协作成员"四角色模式：

| 姓名 | 拼音 | 角色 | 直接负责 |
|---|---|---|---|
| 朱默涵 | zhumohan | 项目经理 | 仓库初始化、README、项目章程、main 分支合并、最终评审 |
| 马振鑫 | mazhenxin | 计划负责人 | 三级 WBS、简化进度计划 |
| 杜航屹 | duhangyi | 配置管理员 | 配置管理文档、分支策略、dev 分支合并、冲突复核 |
| 刘瑞祥 | liuruixiang | 协作成员 | CONTRIBUTING、conflict 演练设计、冲突参与人之一、报告章节 §5/§6 |

### 1.3 协作机制
- 沟通：QQ 群即时沟通 + GitHub issue/PR 节点评审；
- 节奏：5 个里程碑 M1–M5（详见 `docs/01-project-charter.md` §7、`docs/03-schedule.md` §4），节点完成时由配置管理员打 Tag；
- 提交规范：动宾结构 + 中文说明 + `init/docs/fix/merge/chore` 前缀；
- 提交人名称：所有成员仓库级 `user.name` 设置为本人姓名拼音全称。

### 1.4 工作量统计
按照 `docs/03-schedule.md` §3 的预估，每位成员投入约 1.5 人 · 天（含报告撰写与评审）。配置管理员承担额外的合并工作，作为对应角色的常态化职责，未额外计入工作量分配。
