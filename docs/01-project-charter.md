# 01 项目启动说明

## 1. 项目名称
校园活动报名与签到管理系统

## 2. 项目背景
学校拟开发一套面向校内活动场景的轻量级管理系统，需要支持活动发布、报名、名单审核、二维码签到、签到统计与活动结果导出等基础功能。本组在《软件项目管理》课程综合实验中以该题目为统一情境，完成项目管理过程相关的全部交付物，不要求实现完整的业务系统。

## 3. 项目目标
- 支持活动管理人员发布活动信息并维护报名时间、人数上限和活动地点。
- 支持学生查看活动并完成在线报名。
- 支持活动组织者对报名名单进行审核与查看。
- 支持现场签到，并形成签到结果统计。
- 支持活动结束后导出基本统计结果。

## 5. 项目边界
### 5.1 纳入范围
- 项目仓库与目录结构搭建。
- 三级 WBS 文档（围绕交付物分解）。
- 简化进度计划文档（关键活动、工期、前置关系、责任人）。
- 配置管理文档（配置项识别、分支策略、合并规则、版本留痕）。
- 一次完整的冲突制造与解决记录。
- 全员共同完成的总结报告并合并至 `main`。

### 5.2 不纳入范围
- 高保真原型与完整 UI 设计。
- 完整的前后端业务功能开发。
- 复杂支付功能。
- 与校园统一身份认证系统的深度对接。
- 高并发优化与正式部署方案。
- 移动端 App 正式开发。

## 8. 核心约束与假设
- 全部成员每周可投入约 8 学时进行项目管理工作。
- Git 提交人统一使用本人拼音全称，便于贡献核查。
- 所有交付物以 Markdown 作为首选格式，确保可比较与可冲突演练。
- 仓库托管于 GitHub：<https://github.com/dremlory/SoftwareProjectManagement>。

## 9. 沟通机制
- 日常沟通：QQ 群即时沟通。
- 阶段评审：每完成一份交付物由项目经理在仓库 issue 或 PR 中组织一次评审。
- 冲突处理：遵循"先沟通再合并"原则，由配置管理员主导，必要时由项目经理仲裁。
